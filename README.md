# istqb-cn-mock-exam

基于 React、TypeScript、Vite 的 CTFL 4.0.1 中文模拟考试网站。四套正式试卷共 160 题，A 卷附加练习 26 题。题库包含原文解析、学习目标、知识级别以及可放大的原题和解析截图。

网站：https://istqb.azhuquq.com

公开仓库：https://github.com/azhuquq/istqb-cn-mock-exam

## 本地运行

要求 Node.js 22.12+。本地工作目录暂保留 `istqb-mock-exam`，项目与远程仓库名称为 `istqb-cn-mock-exam`。

```sh
npm ci
npm run dev
```

```sh
npm run data:validate
npm test
npm run build
npm run preview
```

## 功能

- 按试卷、章节与错题逐题练习，提交后查看解析。
- A–D 原卷考试：40 题、60 分钟、26 分及格，多选题全对才得 1 分。
- 独立「混合模拟」模块：从全部 186 题（含 A 卷附加题）按官方配额随机抽取 40 题，支持复制、粘贴生成种子来复用相同题目及顺序。
- 答题卡、标记待检查、自动保存、固定截止时间、超时结算。考试途中可确认放弃，舍弃本场作答与标记，不生成成绩或错题。
- 考试报告、章节表现、逐题回顾、考试历史与错题本。
- 手机及桌面布局；题图支持放大、横向滚动查看。
- 键盘操作：`1–5` 选择 `A–E`（多选题可连续选择、再次按键取消），`Enter` 提交练习答案，`← / →` 切换上一题／下一题。模拟考试中 `Enter` 切换当前题的待检查标记，考试报告支持左右切题。快捷键提示位于答题按钮下方，手机屏幕隐藏提示。输入框、选择框、弹窗和组合键不会触发答题快捷键，长按不会连续操作。
- “题库来源”提供 A–D 卷试题与答案解析共 8 份原始 PDF 下载。
- 无账号及后端。学习记录使用当前域名下的 localStorage（`istqb-study-v1`），不会跨设备同步。不同预览域名和正式域名的记录相互独立。

模拟考试仅将已作答但答错的题目加入错题本，未作答题目不加入，仍可在考试报告中回顾。错题答对后仍保留，由用户手动移除。“题库说明与数据备份”页提供 LZ4 备份码的生成、复制、粘贴导入及记录清空功能。导入前显示备份摘要并确认替换；无效备份或保存失败时保留当前记录。

备份格式为 `ISTQB-LZ4-v1:<UTF-8字节数>:<CRC32>:<Base64 LZ4 frame>`，最多支持 8 MiB 原始学习记录。包含练习、错题、历史和进行中的考试；导入不会重置截止时间，过期考试自动结算。复制内容未加密，请妥善保存。导入器在解压前检查帧边界和输出长度，解压后校验 CRC32 与记录结构。自动复制不可用时会选中备份码，支持手动复制。

## 混合模拟与生成种子

侧栏「混合模拟」（`/mixed`）可以随机生成或输入种子复用试卷，点击开始考试才计时。考试页面为 `/exam/mixed`，沿用 60 分钟、26 分及格及单场进行中的考试限制。生成试卷不会覆盖进行中的考试；考试中和报告中都能复制种子，报告的「再考一次」会复用本套种子，每次开考创建独立记录。

抽题遵循 [ISTQB 官方考试结构表 v1.18](https://istqb.org/wp-content/uploads/2026/05/ISTQB_Exam-Structure-Tables_v1.18.pdf) 的 CTFL v4.0 规则。以下每章、每个知识级别题量均为硬性配额，并满足 29 个学习目标组的题量和覆盖规则。组内先抽不同学习目标，再从对应目标中抽题；`FL-5.3.2 / FL-5.3.3` 是跨页的同一组。最终打乱出题顺序，保留原选项顺序，不限制 A–D 各卷的来源题量。

| 章节 | K1 | K2 | K3 | 合计 |
| --- | ---: | ---: | ---: | ---: |
| 1 | 2 | 6 | 0 | 8 |
| 2 | 2 | 4 | 0 | 6 |
| 3 | 2 | 2 | 0 | 4 |
| 4 | 0 | 6 | 5 | 11 |
| 5 | 1 | 5 | 3 | 9 |
| 6 | 1 | 1 | 0 | 2 |
| 合计 | 8 | 24 | 8 | 40 |

随机生成使用短格式 `M1-<题库编号>-<7位Base36随机值>`，当前为 12 个字符，例如 `M1-1-051U7I0`（原版本化格式为 37 个字符）。`M1` 仍指定冻结的抽题算法，题库编号以 Base36 编码，`1` 对应发布表中题库 `1.0.0` 的固定 `seedId: 1`；题库指纹和文件 SHA-256 从发布表读取并校验。随机值仍由浏览器安全随机数生成，完整保留原来的 32 位，使用大写 Base36（0–9、A–Z）编码并补齐 7 位。复用支持首尾空白和大小写归一化。

旧格式 `ISTQB-M1-97B0A3C832E5-12345678` 和 `ISTQB-M1-B1.0.0-97B0A3C832E5-12345678` 继续有效，与短种子 `M1-1-051U7I0` 完全对应，三者复现同一题序。历史记录中的旧种子保持原格式。复用时自动加载对应已发布快照和算法，不支持的算法、未发布版本、指纹或文件校验失败都会明确报错，不替换当前试卷和学习记录。题库不足时也不会放宽配额。

种子只复用题目和顺序，不包含作答与成绩。混合考试的题序、种子、答案及时间保存在原有本地记录和 LZ4 备份中；刷新或导入时按保存的题序恢复，不重新抽题。已有 A–D 原卷记录和备份仍兼容。复制不可用时会选中种子供手动复制。

## 题库与算法版本管理

- `version: 1` 是 JSON 数据结构版本；`bankVersion: "1.0.0"` 是独立的题库内容版本，使用 `major.minor.patch`。文本、答案、解析、来源或裁图有变化时发布新版本。
- `public/data/releases.json` 是发布注册表，指定默认题库与默认算法，登记所有保留版本的路径和校验值，以及短种子使用的固定 `seedId`。编号只增不改，不得重排或重复使用；发布新题库时自动分配下一个编号。当前题库副本为 `public/data/questions.json`，冻结快照为 `public/data/banks/1.0.0.json`。
- `src/algorithms/m1.ts` 冻结当前 Mulberry32、Fisher–Yates、候选排序及官方配额规则。`src/algorithms/index.ts` 按版本调度；改变随机数消费顺序、排序、抽样、配额或其他影响题序的逻辑时，新增 `m2.ts`，保留 `m1.ts`，注册 `M2` 并将其源码 SHA-256 加入发布表，再修改 `currentAlgorithm`。
- `data:validate` 校验所有历史快照、对应裁图/PDF 和已发布算法的完整性，并检查当前副本与默认快照一致；修改冻结文件会导致校验失败，应新增版本。内容指纹规范化排除 `bankVersion` 元数据以兼容已有种子，完整文件 SHA-256 仍包含该字段。
- 新考试记录绑定 `bankVersion`。旧原卷记录默认使用 `1.0.0`，旧混合记录按种子指纹定位。判分、超时结算、报告和历史统计都使用对应版本的题库；导入前先加载并验证所需快照，失败时保留本机记录。已保存题序不重新生成。

编辑当前题库副本后，生成一个尚未发布的新版本：

```sh
npm run bank:release -- 1.0.1
npm run data:validate
npm test
npm run build
```

`bank:release` 只准备本地文件：创建不可覆盖的 JSON 快照，登记指纹、文件和资源校验值，并更新默认版本及当前副本。它拒绝覆盖已发布版本、降低版本号和重复发布相同内容，不执行部署。保留全部历史快照、资源和算法实现，旧种子才能长期复用。

## 题库维护

题库文字与裁图位于 `public/data/questions.json`、`public/questions/`。8 份原始 PDF 位于 [`public/sources/`](public/sources/)，保留原始中文文件名，页面通过同域名链接下载。部署无需 Python 或本机课程目录。来源文件名与 SHA-256 保存在 JSON 的 `sources` 中，构建前校验每份 PDF 的完整性。

重新导入需要 Python 3、Poppler（`pdftotext`、`pdftoppm`）与 ImageMagick（`magick`）：

```sh
python scripts/import-pdfs.py --source-dir '/path/to/the/eight/pdfs' --bank-version 1.0.1
npm run bank:release -- 1.0.1
npm run data:validate
npm test
```

导入脚本把新裁图写入 `public/questions/<版本>/`，不会覆盖历史版本的裁图；同名但内容不同的已有 PDF 会被拒绝，须使用新的来源文件名。原始 PDF 同步到 `public/sources/`，JSON 先写入当前副本，再运行 `bank:release` 冻结发布。导入依据 PDF 的文字坐标识别题目与选项，使用参考答案表匹配答案、章节和知识级别，并对 D 卷重复部分去重。复杂题干保留原图。修改导入逻辑后必须核对跨页题、多选题、图表和解析，不能仅凭题量校验认定内容正确。

## Vercel

GitHub 仓库已连接 Vercel 项目。推送 `main` 自动部署生产站，其他分支生成预览。

`vercel.json` 已配置 Vite 构建与 SPA 路由。构建先校验题库再执行 TypeScript 检查及生产打包；输出目录为 `dist`。

```sh
vercel link --project istqb-cn-mock-exam --scope azhuquqs-projects
vercel deploy --scope azhuquqs-projects
vercel deploy --prod --scope azhuquqs-projects
```

生产域名：`istqb.azhuquq.com`。按 Vercel 返回的要求配置域名 DNS。`.vercel/`、凭证和构建缓存不进入源代码；8 份公开下载 PDF 随仓库和网站发布。
